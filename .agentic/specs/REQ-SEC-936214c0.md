# REQ-SEC-936214c0 — Install from a safe offline self-extracting artifact

## Behavior

The installer validates its exact target and payload before mutation, extracts
only ordinary confined members, simulates an APT transaction against its local
pool, then installs dependencies and the internal package with acquisition
networking disabled. It never selects an adapter, integration or Pi recovery
feature without an explicit supported option.

## Data / interface

`nilo-<version>-<target>.run` is a small POSIX launcher followed by a
deterministic `tar.xz` payload. The launcher finds a fixed marker, copies the
payload into a root-owned mode-0700 temporary directory, validates
`manifest.json` before extraction, and runs `install.sh`. Members use relative
POSIX paths, regular files/directories only, fixed modes and SHA-256 records.
The launcher requires root, `flock`, sufficient space, exact `/etc/os-release`,
architecture and active NetworkManager. APT sources point only at the embedded
pool and all network transports are disabled.

## Examples

The Ubuntu artifact installs on Ubuntu 24.04 amd64 and refuses Ubuntu 26.04,
arm64 and an inactive NetworkManager before state changes. A `../` member,
FIFO or changed `.deb` fails payload verification.

## Acceptance

Parser and container tests cover safe extraction, target/capability/space
preflight, transaction simulation, local-only install and default-disabled
features. Packet/network namespace evidence shows no external attempt.

## Assumptions and open decisions

Internal delivery publishes a separate whole-file SHA-256. Public/customer
distribution stays blocked until a signing and verification-key policy exists.
