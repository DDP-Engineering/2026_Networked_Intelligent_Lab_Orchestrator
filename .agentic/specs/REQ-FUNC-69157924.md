# REQ-FUNC-69157924 — Find retained Modbus evidence with bounded pages

## Behavior

Authorized Find first applies indexed recording identity, timestamp, unit, function, address, outcome and point filters, then matches normalized literal text or even-length hex within that candidate window. Metadata name/tag/date search is independent of event search. The response identifies scope, total or bounded count, next cursor, no-match and truncated states. Search never loads part files wholesale.

## Data / interface

`GET /api/v1/modbus/recordings` lists at most 100 metadata rows with a stable `(started_at,id)` cursor. `GET /api/v1/modbus/recordings/{id}/events` and `/find` return at most 100 events and 64 KiB per page. Event cursor is the recording sequence. SQLite indexes `(recording_id,sequence)`, `(recording_id,unit,function,sequence)`, `(recording_id,outcome,sequence)`, and `(recording_id,point_id,address,sequence)` select candidates. Text/hex search verifies only a capped candidate scan of 10000 rows; if more candidates remain, `truncated=true` and a resumable cursor are mandatory. Hex input is case-insensitive complete byte pairs; regex and arbitrary binary search are unsupported.

## Examples

Searching hex `03 7F` matches a retained `...037f...` frame but rejects odd nibble `037`. A 12000-event search with no hit in the first 10000 returns no matches, `truncated=true` and the next candidate cursor rather than a false definitive no-match.

## Acceptance

Tests inspect query plans or bounded query instrumentation, stable pagination and owner isolation with large rotated fixtures; no search path scans entire JSONL parts.

## Assumptions and open decisions

The capped candidate scan favors bounded work over unbounded arbitrary-substring indexing. The UI must label truncation as partial evidence.
