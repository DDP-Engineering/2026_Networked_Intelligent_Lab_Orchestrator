# REQ-SEC-628657e1 — Fetch immutable packaging inputs

## Behavior

The connected fetch command validates the target registry and complete input
lock before opening a URL. It selects only entries whose `scope` is `shared` or
the selected target. Each response is streamed to a cache-local staging file,
bounded by the declared size, and hashed while reading. The final cache object
appears only after final-URL scheme, size, and SHA-256 validation succeeds.

An already valid object is reused without a request. Any failed or interrupted
transfer removes its staging file. One failed input stops the operation and
leaves previously verified immutable objects available for retry.

## Data / interface

The lock is UTF-8 JSON:

```json
{
  "schema": 1,
  "complete": true,
  "incomplete_reasons": [],
  "inputs": [
    {
      "name": "ubuntu-package-example",
      "scope": "ubuntu-24.04-amd64",
      "url": "https://example.invalid/package.deb",
      "version": "1.2.3-1ubuntu1",
      "license": "MIT",
      "sha256": "64-lowercase-hex-characters",
      "size": 1234
    }
  ]
}
```

Rules:

- unknown fields are errors;
- a complete lock has no incomplete reasons and at least one input; each
  operation additionally requires a shared or target-scoped selected input;
- an incomplete lock has at least one reason and cannot be fetched, verified,
  or prepared;
- `(scope, name)` is unique and entries are ordered by scope then name;
- scope is `shared` or one declared target;
- `name` is lowercase ASCII letters, digits, dots, underscores, and hyphens;
- `version` and `license` are non-empty provenance strings and are reproduced
  in verified inventories and preparation receipts;
- source and final redirect URLs are HTTPS, contain no credentials or fragment;
- SHA-256 is exactly 64 lowercase hexadecimal characters;
- size is a positive integer.

Objects use a tool-derived path, never a lock-provided path:
`<cache>/objects/sha256/<first-two-hex>/<sha256>`. Staging files live below
`<cache>/.staging/`.

The command is:

```text
fetch --targets <targets.json> --lock <inputs.lock.json>
      --cache <directory> --target <target-id>
```

## Examples

A 1234-byte response with the declared digest is atomically installed.
A response that produces byte 1235 is rejected immediately and leaves no final
object. A redirect whose final URL is HTTP is rejected even if its bytes match.

## Acceptance

Automated tests inject response streams and confirm provenance retention, valid
reuse, successful atomic placement, missing-provenance and malformed or
scheme/credential/fragment URL rejection, oversized and undersized responses,
digest failure, interruption during open and streaming, cleanup, duplicate
rejection, and target filtering.

## Assumptions and open decisions

Authentication-bearing downloads are not supported. Inputs requiring
credentials must be acquired through a separately reviewed escrow mechanism
before they can enter a complete production lock.
