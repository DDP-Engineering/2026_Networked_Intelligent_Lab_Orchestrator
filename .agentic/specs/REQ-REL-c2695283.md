# REQ-REL-c2695283 — Structured Sigrok worker boundary

## Behavior

SW-01 introduces a feasibility worker, not the SW-02 public capability API. The worker is a native executable launched beneath the existing Python integration runner. It calls libsigrok and libsigrokdecode directly and writes bounded newline-delimited JSON records to standard output. Diagnostics use standard error. One invocation performs one allowlisted operation and exits; the parent owns deadline, output-budget, exit-status, and signal handling.

The feasibility operations are `demo-capture` and `uart-fixture`. They accept no driver-defined passthrough settings. `demo-capture` opens only the libsigrok Demo driver and applies only an internal finite sample limit. `uart-fixture` feeds an internal deterministic logic waveform to the installed UART decoder. Neither operation exposes output modules, signal generators, PWM channels, or configuration setters to callers.

## Data / interface

Invocation:

```text
nilo-sigrok-worker demo-capture --samples <1..4096>
nilo-sigrok-worker uart-fixture
```

Every stdout line is one JSON object with `schema: "nilo.sigrok.worker/1"`, `kind`, and kind-specific fields. Sample positions and byte counts are decimal strings. Record kinds are:

- `runtime`: libsigrok/libsigrokdecode package and ABI versions and host/build evidence when available.
- `driver`: stable driver ID and display name.
- `device`: vendor/model/version/serial/connection fields when provided.
- `channel`: index, stable native name, `logic` or `analog`, and enabled state; names containing `PWM` are never emitted.
- `channel_group`: native group name and channel indices.
- `setting`: native key/id/name/type, `device` or `group` scope, get/set/list flags, and typed `current`/`values` when calls succeed. Output-class keys are suppressed, and unknown native values are represented with an explicit native type plus bounded text rather than guessed semantics.
- `packet`: `logic` carries unit size, byte count, sample count, and bounded lowercase hexadecimal bytes; `analog` carries channel indices, count, measurement quantity/unit/flags, and converted numeric values.
- `event`: `header`, `metadata`, `trigger`, `frame_begin`, `frame_end`, or `end`, in callback order.
- `decoder`: installed decoder identity, channel and option descriptors using native GVariant types.
- `annotation`: decoder/instance IDs, decimal start/end samples, annotation class, and ordered text variants.
- `binary`: decoder/instance IDs, decimal start/end samples, binary class, byte count, and bounded lowercase hexadecimal bytes.
- `summary`: record counts, truncation flags, and explicit booleans showing whether logic, analog, trigger, frame-begin, and frame-end packets were observed.
- `error`: stable error code and bounded message; a fatal error is followed by a nonzero process exit.

Limits: at most 4096 requested Demo samples, 256 total records, 4096 logic/analog values across emitted packet previews, 200 capture or decoder callback records, 1 MiB total stdout, and 4 KiB per record. The lower native callback caps leave room for capability/catalog/runtime/summary records. The parent treats malformed JSON, wrong schema, duplicate terminal summary, extra stdout after summary, budget excess, timeout, signal termination, or nonzero exit as worker failure.

## Examples

A Demo analog packet can be represented as:

```json
{"schema":"nilo.sigrok.worker/1","kind":"packet","packet":"analog","sample_count":"16","channels":[8],"unit":"volt","values":[0.0,0.1]}
```

A fixture annotation can be represented as:

```json
{"schema":"nilo.sigrok.worker/1","kind":"annotation","decoder":"uart","start_sample":"16","end_sample":"96","class":0,"texts":["55"]}
```

An attempt to select `atk-dl16:conn=1.3:pwm=on` has no grammar in this protocol and is rejected before any native configuration setter can run.

## Acceptance

Tests parse every example against the worker schema contract, require both digital and analog packet fixtures plus event records, reject PWM/output tokens recursively, and exercise parent containment of crash/timeout/oversize/malformed output. A target proof compiles the worker against the deployed ABI and records Demo plus libsigrokdecode callback output. The evidence report names runtime versions and clearly separates Demo/fixture integration behavior from physical/electrical qualification.

## Assumptions and open decisions

The deployed 0.6.0 libraries expose ABI 4 and are compatible with the inspected matching source headers. Demo is expected to provide mixed logic/analog data, but trigger and frame packets are reported as observed/absent rather than invented. SW-02 will define the public request schema and stable capability semantics after this proof; SW-01 does not promise that every native key or device class becomes a waveform control.
