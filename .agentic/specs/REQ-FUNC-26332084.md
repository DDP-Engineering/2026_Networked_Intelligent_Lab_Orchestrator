# Managed sigrok integration

## Scope and behavior inventory

The task's 16 requirements cover final product lifecycle and interfaces. Tooling
is implementation detail. PulseView/sigrok correctness and broader analyzer
features are deferred. PWM is excluded. Use the existing CLI without modifying
the fork. A small capture on the authorized Pi is integration evidence only.

## Interface and ownership

`/api/v1/plugins` lists curated available packages and installed state.
`/api/v1/plugins/{id}/{install,enable,disable,restart,uninstall,discover}` provides
typed actions; enable accepts policy mode ask/auto. Disable blocks new work and
keeps an active job draining; restart and uninstall refuse busy instances.
`/api/v1/bench/jobs` lists/submits jobs. Submit names plugin, operation, device,
typed parameters and an idempotency key; no executable or path is accepted.
Job reads/actions and artifact download are authorized with the same core
service from HTTP, CLI and MCP. Only browser-session humans holding approval
permission may approve pending jobs; token users cannot self-approve.

Installed state and enablement persist in SQLite. Installation copies a
trusted, validated, digest-listed package from a configured local bundle into
the data directory. The operator cannot submit an arbitrary filesystem path.
The runner executable must be confined by the existing manifest loader and
supervisor. Python SDK environments are constructed during bundle preparation,
not by API requests. Curated runtime configuration is server-owned.

Existing operation service is extended with separate prepare/run entry points;
the original synchronous Submit remains for current consumers. Bench service
owns background contexts, job result storage, scoped supervisor instances and
confined artifact transfer. Existing policy snapshots, sessions, leases and
artifact store remain authoritative. Restart reconciles interrupted sessions
without replay. Jobs and artifacts remain after uninstall.

## Runner contract

Python SDK runner uses existing execute methods `discover_devices`, `capture`,
`decode_uart`. Device listing is a typed semantic result of discover_devices;
the protocol's status-only discover control remains a health/lifecycle control.
This uses nilo.integration/1 without adding unknown fields. All stdout remains
NDJSON. Child CLI output is drained/bounded separately.

Capture accepts conn, digital channel list D0-D15, one supported sample rate,
finite count no greater than one million and timeout no greater than 30 seconds.
Core resolves device connection, staging paths and backend runtime; callers
cannot override them. Backend repeats validation and builds an argv array.
Simulated mode produces deterministic srzip data and is explicitly labelled.
Real mode scans only atk-dl16, captures srzip, records CLI/runtime metadata and
checks format/sample metadata before declaring evidence. PWM is absent from
discovery and refused as an input. No trigger, PWM or arbitrary config controls.

Saved UART decoding takes an authorized completed capture and bounded decoder
options, returning original annotations with sample offsets. Detailed decoder
correctness is not claimed. Downloadable artifacts and a bounded sample preview
support inspection without implementing the full PulseView GUI.

## Failure and lifecycle semantics

Default policy is ask, installed packages are disabled, enablement is explicit.
Execution authorization differs from package management and human approval.
Idempotency is keyed by owner plus key and compares canonical requests. Reuse
with different inputs conflicts. Cancellation awaits process-tree cleanup
before lease release. Pending cancellation denies the request. Failed output
is never a completed capture. Artifact reads enforce owner/admin access.
Concurrent hardware operations claim the same physical device key. Offline
analysis has no hardware claim. Package lifecycle never deletes history.

## Concurrent transactions and delayed responses

Admission persists job ID, session/request IDs, actor, canonical parameters,
idempotency key and absolute deadline before acknowledgement. A bounded queue
(maximum 32 nonterminal jobs) returns explicit queue_full on overflow. Scheduler
runs at most two workers and serializes jobs sharing a hardware resource;
independent resources may proceed. Queued work has the same overall deadline
as running work (default 60 seconds, maximum 300 seconds). Runner execution
is additionally bounded to 30 seconds for this finite capture slice.

Reply/progress records persist with transaction ID and increasing sequence.
Clients query jobs/replies using those IDs, not connection lifetime or arrival
order. Existing strict wire correlation rejects unknown, duplicate-terminal
and late-after-terminal responses. Bounded retained events and durable terminal
results permit reconnect without retaining open HTTP/MCP calls. Pending-approval
and queued cancellations settle without acquiring hardware; running cancellation
keeps ownership until cleanup finishes. Restart marks unfinished work incomplete
and never automatically resubmits it. Disable prevents queued work from starting
and settles it explicitly while an already-running capture drains.

List endpoints return transaction summaries; individual reads return up to 100
ordered replies (4 KiB each) and a terminal result (1 MiB). Acquisition and decode
are durable jobs; lifecycle and discovery use bounded synchronous control calls.
Artifact declaration ID is `capture`, with a confined `capture.sr` filename.
