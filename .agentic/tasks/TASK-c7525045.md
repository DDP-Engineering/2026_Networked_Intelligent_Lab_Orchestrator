## Frame

Problem: MB-04 has live raw Modbus sessions, but no shared named register maps, typed value codec, definition interchange or saved workspace metadata. Gitea #32 is the next work package.
Desired outcome: Revisioned shared map/workspace definitions with safe typed decoding and encoding, explicit address notation, dry-run and atomic CSV/JSON interchange, and equivalent Core interface access without opening a transport.
Actors: Administrator, Operator map/workspace creator, another Operator, Viewer, Core, CLI and MCP clients.
Primary scenario: An Operator creates a named map of typed points, saves a workspace referencing exact map/profile revisions, exports and imports definitions with preview, then opens the workspace for inspection; no device session or write starts.
Examples: Holding reference 40001 denotes wire offset 0; a swapped 32-bit word pair decodes predictably; uint64 crosses JSON as a decimal string; duplicate import reports a conflict before publication.
Counterexamples: Base-1 address zero, an int64 JSON number rounded by JavaScript, a zero inverse scale, two point spans overflowing register 65535, another Operator overwriting the creator's map, or opening a workspace creating a live session.
In scope: Core map/workspace models and revisioned SQLite storage; point validation/address presentation; finite typed raw-word codecs and write-value validation; bounded UTF-8 CSV/JSON map interchange with preview and atomic publication; save/list/get/duplicate/export/import for maps and workspaces through authenticated HTTP, CLI and MCP; tests and current component knowledge.
Out of scope: MB-06/07 GUI pages and live grid, MB-08 recordings, MB-09 advanced functions/scans, live connection or device I/O, deployment, Git staging/commit/push, unrelated untracked `09_Others` media.
Constraints: STATED user-confirmed client only, RTU-over-IP TCP only, shared definitions with creator/admin editing and one live owner, plugin-level successive-write policy, same branch and AEGIS autopilot. OBSERVED MB-01 strict map/workspace contract, MB-02 definition repository, MB-04 raw session API and pinned read plans. Saved metadata cannot mutate a live session implicitly.
Success signals: All address bases reject overflow; golden type/order/NaN/int64/inverse-scale vectors pass; expected revisions and owner checks reject stale/foreign writes; import preview enumerates row/conflict errors and invalid imports publish nothing; save/open/duplicate/export round trips without transport I/O.
Evidence: STATED current instruction and prior user decisions; OBSERVED Gitea #32, `00_Planning/Modbus_Plugin_Plan.md` sections 1,6,8,10, `REQ-DATA-6fcda58c` spec, `schemas/contracts.schema.json`, Core `internal/modbus/definitions.go`, `modbus_repository.go`, `modbus_session.go`. INFERRED Core must own new metadata services rather than the private runner.
Assumptions: The MB-01 schema is a structural baseline; MB-05 adds semantic validation and may add optional fields needed for the confirmed type/CSV contract. Revisioned workspace references are validated on save/open rather than auto-applied to an existing session.
Unknowns: Actual device maps, hardware-specific text encodings and physical read/write limits remain later target acceptance. The first implementation uses documented bounded UTF-8 metadata and ASCII register strings.
Decision-blocking questions: None; ticket and confirmed plan settle scope, while exact codec/interchange choices are design details to document.
Proposed behaviors: Validate and store map/workspace metadata with optimistic revisions and creator/admin authority; decode/encode supported types from exact raw words; preview and atomically import CSV/JSON; expose matching metadata actions through HTTP/CLI/MCP without any implicit connection.

## Design

Requirements coverage: `REQ-FUNC-3277269b` uses a pure canonical model and address conversion; `REQ-FUNC-d0c39b60` uses a pure reversible word codec (exact integer rational scaling); `REQ-FUNC-dd8ff122` and `REQ-FUNC-e14acc2b` use revision-checked SQLite documents and Bench authorization; `REQ-DATA-723c5581` uses a bounded parser/preview and one publication call; `REQ-FUNC-3584cdf3` routes three surfaces to those Bench methods.

Core `internal/modbus` owns structural and semantic models, conversion and map interchange. SQLite owns documents and expected-revision compare-and-swap. Bench owns actor permission, creator retention, cross-definition reference checks, workspace JSON preview/import and audit. HTTP, CLI and MCP are adapters; no runner/session call is introduced. Saved workspace opening reads metadata and verifies references, with no live plan mutation. [all six requirements]

The models retain MB-01 schema version 1 and add optional description, precision, padding fields. Point addresses persist as zero-based wire offsets; API conversion accepts zero/one/reference explicitly. Floats are IEEE 754 and 64-bit integer JSON values are decimal strings. Import is capped at 1 MiB/4096 points; errors and conflicts are returned before one atomic save. [REQ-FUNC-3277269b, REQ-FUNC-d0c39b60, REQ-DATA-723c5581]

New definitions have revision 1 and actor owner; updates require current revision and creator/admin. Repository transactions enforce one revision increase; conflicts do not partially publish. Workspace validation requires existing current endpoint/profile/map revisions. The existing live session remains pinned and independent. [REQ-FUNC-dd8ff122, REQ-FUNC-e14acc2b]

Migration 026 adds current map/workspace document tables and immutable revision tables for profiles, maps and workspaces, backfilling existing current profiles. A workspace can keep resolving pinned profile and map revisions after later edits. Existing endpoint/profile rows and public routes stay compatible. A failed migration rolls back using the existing migration transaction; failed import has no durable effects. Bench audit records save/duplicate/import requests and outcomes. Focused tests attach to model, codec, repository/Bench and surface seams. [REQ-FUNC-dd8ff122, REQ-FUNC-e14acc2b, REQ-FUNC-3584cdf3]

### Proposed architecture - TASK-c7525045

`HTTP / CLI / MCP -> bench.Manager -> internal/modbus model+codec+interchange`
`bench.Manager -> sqlite.ModbusRepository -> current maps/workspaces + immutable revisions`
`bench.Manager -X-> live Modbus runner/session (definition operations)`

Alternative of storing definitions inside the Python runner was rejected because Core must authorize and share them. Risk: CSV spreadsheet round trips and 64-bit scaling need golden vectors; stale workspace references must be explicit errors. Open decisions: none for this ticket; device-specific encodings remain later work.
