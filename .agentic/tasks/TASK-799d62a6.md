## Frame

Problem: an installer commissioning an appliance over a direct Ethernet cable
has no DHCP server and no address to guess. NILO's saved addressing model offers
only automatic and static, so there is no way to express the one method that
needs neither.

Desired outcome: a wired adapter can claim an IPv4 link-local address, and an
adapter holding only such an address is a management path like any other.

Actors: an administrator saving an adapter configuration; the privileged helper
rendering it for NetworkManager; first-boot provisioning, which admits whatever
address an eligible adapter reports.

Primary scenario: a wired adapter is configured for link-local -> the helper
renders the NetworkManager link-local IPv4 method -> the adapter probes its way
to a 169.254 address and carries management access on it.

Examples: a laptop connected straight to the appliance's Ethernet port reaches
it without either end being configured.

Counterexamples: link-local combined with a static address or gateway is
refused, because the method means the address is not configured; link-local on a
wireless adapter is refused, because it would promise a joined network that
cannot route.

In scope: the addressing method, its validation, its NetworkManager rendering,
and the tests proving a link-local-only adapter is a usable management path.

Out of scope: automatically applying the method during provisioning, exposing it
in the browser interface, and the appliance image's NetworkManager default.
See the open decision below.

Constraints: the existing addressing model is a closed set validated in one
place, and the helper renders it for NetworkManager behind the Linux build tag.

Success signals: the method validates only where it is meaningful, the helper
compiles and vets for Linux with it, and an adapter whose only address is
link-local is reported eligible and usable.

Evidence:
- OBSERVED `internal/network/interface_settings.go` - `AddressMethod` was
  `automatic` and `static` only, validated in one `switch`.
- OBSERVED `internal/nethelper/networkmanager_settings_linux.go` - `ipv4Settings`
  renders `manual` and `auto`; NetworkManager's own `link-local` method is the
  natural third.
- OBSERVED `internal/network/management_access.go` - `rebuildAllowedLocked`
  admits every address an enabled interface reports and filters none, and
  `managementConfigurationHasUsableInterface` counts any address, so a
  169.254 address already makes an interface usable. No change was needed there,
  and the test pins that.
- STATED (user, issue #6) - "Define a safe IPv4 link-local fallback for eligible
  Ethernet interfaces without DHCP/static addressing so direct commissioning does
  not require guessing an address or supplying a DHCP server" and "Avoid
  assigning the same conventional static provisioning address to multiple
  interfaces when that would cause route or ARP ambiguity"; acceptance test 4.
- INFERRED - the standard link-local probe already gives each adapter a distinct
  address, which is precisely what the ticket's warning about a shared
  conventional address asks for, so NILO does not allocate addresses itself.

Assumptions: NetworkManager's `link-local` IPv4 method is available on the
appliance platform, which is the same NetworkManager the rest of this package
drives.

Unknowns: whether the appliance image should additionally make link-local the
standing fallback for an unconfigured Ethernet adapter, so that acceptance test 4
holds with no saved configuration at all. Recorded as an open decision rather
than assumed.

Decision-blocking questions: none for this candidate; one open decision is
carried below for the human.

Proposed behaviors:
1. A wired adapter accepts link-local as its addressing method, and the method is
   refused with a static address, with a gateway, or on a wireless adapter.
2. An adapter whose only address is link-local is a usable, eligible management
   path.

Path and reason: full. A new value in a validated data model and a new rendering
in the privileged helper; no existing requirement covers it.

## Design

**Requirements coverage.** REQ-FUNC-9a19ad36 is carried by one value in
`AddressMethod`, one arm in the settings `switch`, and one arm in the helper's
`ipv4Settings`.

**Interfaces and contracts.** `MethodLinkLocal` joins the closed `AddressMethod`
set. `InterfaceSettings.Validate` refuses it with a static address or gateway,
because the method means the address is not configured, and refuses it on a
wireless adapter, because a link-local address reaches only the segment a cable
is on. The helper renders it as NetworkManager's `link-local` IPv4 method.

**Deliberately unchanged.** The management allowlist needed no work: it admits
every address an enabled interface reports, so an adapter that probes its way to
a 169.254 address is admitted by the derivation delivered in TASK-20c64f67. The
test pins that rather than assuming it.

**Alternatives rejected.** Allocating a conventional address per adapter, such
as a fixed 192.168.x.1 - the ticket warns against exactly that, because two
adapters carrying it would create route and ARP ambiguity. The standard
link-local probe already reaches a different address on each adapter.

**Expected files.** `internal/network/interface_settings.go`,
`internal/network/link_local_test.go` (new),
`internal/nethelper/networkmanager_settings_linux.go`.

**Open decisions.** Whether the appliance image should make link-local the
standing NetworkManager fallback for an unconfigured Ethernet adapter. Acceptance
test 4 asks that direct commissioning work with nothing configured, which this
candidate makes expressible but does not make automatic. Two ways to close it:
a NetworkManager system default shipped with the image, which is deployment
configuration and belongs with the installer work that is not on this branch; or
NILO applying the method itself during provisioning, which would mean an
automatic network change with no acknowledgement or rollback window, through
machinery built around both. That is a security and product decision, not an
implementation detail, so it is recorded here rather than chosen.
