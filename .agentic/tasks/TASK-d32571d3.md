## Frame

Problem: NILO has Camera, Serial and Sigrok families but no Modbus master workspace; the user wants a plan informed by Radzio and Modbus Poll, following existing administration/instrument separation.
Desired outcome: Saved implementation plan in 00_Planning, with reference analysis, controls, RTU/TCP/RTU-over-IP, definitions/maps, logs/search/export and Gitea implementation tickets carrying the plan.
Actors: Administrator, operator, viewer, credential-bound live owner, GUI, CLI/MCP client, Bench Core, supervised Modbus runner and connected units/gateways.
Primary scenario: Admin configures a named endpoint -> operator opens a shared workspace/map -> approved session polls several units -> explicit write uses policy -> retained recording can be searched/exported offline.
Examples: Concurrent RTU adapters alongside a camera; one RS485 bus polling units 1 and 2; holding reference 40001 represented as wire address 0.
Counterexamples: Terminal and Modbus both owning one tty; uncertain write retried automatically; loading a saved session transmitting writes; TCP identity fabricated as USB metadata; scans assumed harmless for every vendor.
In scope: Planning document and index, frame journal, primary-source research, ten bounded implementation work packages and authorized Gitea issue publication through tea.
Out of scope: Production implementation, formal requirement creation, code tests, release/version change, Git state mutation, deployment and real hardware/network operations.
Constraints: Explicit output path is 00_Planning; Git authority is limited to reads; existing project contracts, shared services, reproducible toolchains and target acceptance remain authoritative.
