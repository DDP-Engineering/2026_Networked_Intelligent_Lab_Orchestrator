## Design

**Device networks and audit extension (2026-09-03).** The contracts are in
`.agentic/specs/REQ-FUNC-2f8d63b5.md`. This note records only the decisions and
the seams, in the order the phases build them.

*Identity before events (REQ-DATA-58f3c012).* A new `internal/appliance`
package owns the stable appliance identity and the per-boot identity, and the
identity is read or created while the application opens, before any service that
could record an event exists. Rejected alternative: deriving the identity from
hostname, MAC or IP, each of which changes for reasons that have nothing to do
with the appliance being a different appliance, and each of which two cloned
images would share anyway.

*One audit writer, additively extended (REQ-DATA-91e7ab46).* `audit.Event`
grows an envelope rather than gaining a second table, and every new column is
written as "not recorded" for a row the old writer produced. A new
`audit.Writer` in `internal/audit` fills the envelope fields nobody should have
to remember - appliance, boot, category, severity, time source - so a caller
supplies only what it actually knows. Rejected alternative: a parallel
`network_events` table, which would make "what happened on this appliance" two
queries that can disagree, and would leave the existing identity events outside
the Activity page.

*A persisted sequence allocator (REQ-DATA-2c8b5f79).* Ordering comes from a
single-row `audit_sequence` table updated in the same transaction as the insert,
not from `MAX(sequence)+1`. The current expression is correct only while rows
are never deleted, and this milestone adds retention, so it would silently start
handing out numbers that have already been used.

*Operations become durable rows (REQ-FUNC-97c1e5d8, REQ-REL-2e91cb74).*
`OperationManager` keeps its in-memory map as the working set and gains an
optional `OperationStore` it writes through, so a restart can list what was in
flight and reconcile it against the helper's own record. The store is optional
because the simulation profile and every existing unit test construct a manager
without a database, and making persistence mandatory would turn a durability
feature into a construction failure. Rejected alternative: reading the
operation state back out of SQLite on every request, which would put the single
SQLite connection on the path of a poll that runs every second.

*Audit is written where the effect happens, not at the HTTP boundary
(REQ-DATA-91e7ab46).* The operation manager records requested, applied,
confirmed, rolled-back and recovered outcomes itself, because the GUI, the CLI,
the expiry ticker and the startup reconciler all reach the same lifecycle and
only two of them are HTTP requests. Rejected alternative: middleware, which
sees the request and not the outcome, and never sees the timeout that fires
when nobody is there.

*Refusal before side effects when audit is unavailable (REQ-REL-59e4f80c).* The
manager records the accepted intent before it touches anything, so a storage
failure refuses the change while nothing has happened yet. Reads, established
forwarding and recovery deliberately do not consult the audit store at all, so a
full disk cannot prevent a rollback.

**Compact network presentation (user correction, 2026-09-03).** Keep one persistent runtime badge in TopRow, remove authenticated shell footer and per-section source prose, and make gateway4/gateway6 additive public observations from NetworkManager IP configuration. Preserve API measurement provenance and sign-in boundary. Show safe WireGuard addresses/endpoints, put DNS/routes/handshake and readiness diagnostics in collapsed details, and open import only when requested. Compact the chart toolbar; retain authorization, acknowledgement, rollback, stale-data and error handling. ### Acknowledged installation increment

The optional asynchronous installation controller starts a helper-owned bounded job after the existing actor/revision acknowledgement. Core maintenance polls progress and reserves network mutation until terminal status. The privileged engine serializes installation with recovery, persists installation status in its private directory, and marks interrupted work failed at restart without replay. Fixed Debian 13 / Ubuntu 24.04 APT commands install only wireguard-tools: fresh signed indexes, strict source options, simulated transaction rejecting changes to any other package, pinned candidate, download then recheck and install. Neither packages nor commands/paths come from RPC. Errors and progress are fixed public messages, no raw repository output. Readiness is re-probed after installation, while tunnel profile management remains unavailable. The systemd helper requires explicit package database, package payload and network access; disposable container tests exercise actual installation, idempotence, locks and offline repositories before a full gate. Files: internal/network/install*, internal/nethelper/install*, protocol/client/engine/store/wireguard, helper startup, HTTP operation response, GUI operation progress/capability, installer systemd template, and network container harness.

**Live WireGuard readiness increment (REQ-FUNC-c7057156).** Add a parameterless
`wireguard.check` helper read, surfaced by the existing service/HTTP/CLI/MCP.
Probe NetworkManager over D-Bus, kernel support from the loaded module or exact
running-kernel configuration/module metadata, and the required `wg` tool using
only a compiled absolute path and `--version`; never run wg-quick, load modules,
create a tunnel or invoke a shell. Inconclusive probes keep `reported: false`
with a diagnostic instead of asserting the kernel is unsupported. Installation
and profile management remain refused until their own implementation lands.

**Live interface increment.** Add internal/nethelper as the root-owned typed RPC, durable recovery engine and NetworkManager D-Bus adapter; internal/network remains process-free. Extend recovery with an optional exact-change preparer so the helper persists and binds the requested target/action before checkpoint creation and applies only that saved request. One root-owned journal stores pending/terminal recovery and runtime-disabled connection choices, with fsync/rename and no secret settings. NetworkManager owns the independent timer; helper startup and Bench Core startup reconcile pending changes before new requests. Re-probe the saved connection, device autoconnect, addresses, routes and DNS before declaring recovery successful. The helper authenticates Unix peers before reading bounded JSON, refuses arbitrary paths/operations, and has no remote recovery-clear method. The first live mutation surface is Ethernet/Wi-Fi enable/disable; WireGuard writes stay explicitly unsupported until their own recovery and key-storage work is verified.

**One service, two providers (REQ-PLAT-c3923cad, REQ-PLAT-51573984,
REQ-FUNC-26248271).** `internal/network` owns a `Service` that HTTP, CLI and
MCP all call, behind a `Provider` interface with two implementations:
`provider_simulated.go`, dependency-free in the manner of `simulation.Catalog`,
and `provider_linux.go` over NetworkManager's D-Bus API. The profile chosen at
`serve` selects one, and the simulated provider has no helper client at all —
it cannot reach the host because nothing is wired to it, not because a flag
says not to. A device another manager owns is returned by the provider as
observable and not manageable, which is one field rather than an exclusion.
Rejected alternative: one provider with runtime branches on the profile, where
a missed branch is a live host change on a developer's workstation.

**A separate root binary, not elevation inside Bench Core (REQ-SEC-144b5e56).**
`cmd/nilo-nethelper` runs as root behind a `0660 root:nilo` Unix socket and
checks `SO_PEERCRED` before reading a byte; Bench Core stays unprivileged and
speaks one typed JSON object per connection against a compiled-in allowlist.
Rejected alternative: `sudo` or a polkit action, both of which accept a command
line — precisely the arbitrary-command surface the requirement forbids, and a
surface that grows every time a new operation is added.

**NetworkManager owns tunnels; `wg-quick` is never invoked
(REQ-FUNC-faf2f697, REQ-SEC-ef45d243).** Profiles are imported into NILO-owned
NetworkManager connections after the `.conf` is parsed by our own reader, which
rejects `PreUp`, `PostUp`, `PreDown`, `PostDown` and unknown directives by name.
Rejected alternative: handing the file to `wg-quick`, which is a shell script
that executes those hooks — importing a profile would mean running whatever the
supplier wrote.

**Two rollback layers, because one is not enough (REQ-REL-ad0fea46,
REQ-REL-67b09885).** NetworkManager's checkpoint with a 120-second rollback
timeout is the primary: it fires inside NetworkManager even if Bench Core, the
helper and the browser are all gone. The helper's `recovery.json`, written
before connectivity is touched, is the reconciliation backstop for a reboot or
a checkpoint that outlived its daemon, and it is what makes "restored" an
observation rather than an assumption. Rejected alternative: a timer in Bench
Core, which dies with the process that most likely just cut its own network.

**Acknowledgement reuses the digest technique, not the policy resolver
(REQ-SEC-43b5fe46, REQ-FUNC-a6495c6d).** The canonical-JSON digest that binds
`policy.ApprovalRecord` to an immutable request is the right mechanism, so the
preview digest is built the same way, including the observed state so a preview
goes stale when the world moves. But `policy.Resolver` answers "may this run
without a human approval" for an integration app's operation, and a network
change always requires an administrator; routing network changes through it
would make the two questions one. Rejected alternative: extending
`policy.OperationPolicy` with network actions, which would let an integration
manifest have an opinion about the appliance's own networking.

**Statistics are minute rows with no zero-fill (REQ-DATA-af764873,
REQ-DATA-bd03ae66, REQ-FUNC-0aa94b00).** One `STRICT` table keyed by interface
and minute, written from five-second samples over monotonic elapsed time, with
a `samples` count so a reader knows how complete a row is. A minute with no
usable sample is simply absent. Rejected alternative: writing a zero row for a
missing minute, which turns "we did not measure" into "there was no traffic" —
the one confusion the plan calls out by name.

**The CLI is an API client (REQ-FUNC-56c96968, REQ-SEC-7861a0b2).**
`cmd/nilo/network.go` over a new `internal/apiclient`, calling the same
authenticated routes as the browser even on the appliance, with no `--token`
flag anywhere in the flag set. Rejected alternative: calling the service
in-process when local, which would give a shell user on the appliance a second
authorization path with different rules.
