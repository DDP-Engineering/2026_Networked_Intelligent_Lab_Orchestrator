## Design

- pages.ts owns reported-inventory eligibility. A shared managed-device predicate requires all four explicit flags/states. Camera/Serial groups exist only with eligible children; installed/enabled/ready plugin gates apply first.
- Other integration entries require healthy/ready integration status and usable reported hardware. When a managed package exists its installed/enabled/ready state is authoritative. Legacy analyzer device rows without managed flags remain governed by ready integration/device inventory.
- AppShell separates menu visibility from its retained route list. A failed plugin refresh or unavailable Core hides Instruments in SideNav and NavDrawer, retaining open tab state until a successful inventory authoritatively removes a route.
- No permission or hardware operation changes. Records and saved media remain stored. No backend availability claim stronger than reported state.
- Tests attach to pages.test.ts, serialNavigation.test.ts and shell.test.tsx. Existing route/shell and full browser suite cover regressions.
- Expected files: shell/pages.ts, AppShell.tsx, their tests, GUI knowledge, Camera navigation requirement, new shared requirement, changelog.
